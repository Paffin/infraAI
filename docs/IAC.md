# Инфраструктура как код

Из одной модели архитектуры генерируются **манифесты Kubernetes**, **Helm (helmfile)** и **Terraform/OpenTofu**. Это не каркас и не
заглушки: каждый объект выведен из схемы по шаблону, проверен на соответствие настоящим схемам Kubernetes и CRD операторов, а то, что
сгенерировать нельзя, перечислено в отчёте с причиной. Секреты не генерируются никогда.

> «Без заглушек» — принцип, а не лозунг: если у компонента нет честного генератора (облачный DNS, гипервизор, WAF), экспорт так и
> скажет, а не вставит пустой модуль. Чтобы получить генератор, добавьте шаблон (см. ниже) — никакой код менять не нужно.

## Как схема превращается в код

```
схема ─► план (какой кластер что запускает) ─► объекты и релизы ─► kubernetes / helm / terraform
           │                                      ▲
           └─ отчёт: что сгенерировано, что нет, ─┘  шаблоны IaC по видам компонентов (данные, редактируются в админ-панели)
              что поставить сначала, какие секреты создать
```

1. **Кластеры.** Кластер — это компонент вида с признаком `k8s-cluster` (в каталоге по умолчанию — «Kubernetes»; признак задаётся в
   `export.k8s.clusterTrait`). Каждый такой узел — отдельный кластер, **если** не задано свойство «Имя кластера» (`clusterName`):
   узлы с одним именем образуют один кластер, растянутый на их зоны (например, три AZ региона). Эталонные архитектуры
   «3 AZ в одном регионе» и «Событийная шина» используют это; «2 ЦОД» — по кластеру на ЦОД.
2. **Размещение.** Компонент разворачивается в кластере своей зоны (или ближайшей родительской). Свойство «Размещение» (`hosting`):
   `auto` — в кластере зоны, если он есть; `kubernetes` — то же, явно; `vm` и `managed` — не разворачивать (балансировщики L4/L7
   по умолчанию `vm`: перед кластером они обычно живут вне него).
3. **Рабочие нагрузки.** Узлы одной группы (`group`) — один сервис; в каждом кластере он превращается в одну нагрузку (`site`):
   экземпляры суммируются, роль `primary` определяет ведущую площадку, остальные становятся репликами (для PostgreSQL —
   реплика-кластер, потоково реплицирующийся с ведущего). Арбитры (`witness`) экземпляров не добавляют.
4. **Шаблон вида.** Что именно получится — решает шаблон IaC этого вида (`config item` вида `iac`): CR оператора, чарт Helm, нужные
   данные, условия отказа.
5. **Отчёт.** Для каждой группы — `generated` или `skipped` с кодом причины; предупреждения, предварительные требования (операторы
   с зафиксированными версиями) и секреты, которые нужно создать.

Причины, по которым компонент попадает в «не сгенерировано»:

| Код | Смысл | Что делать |
|---|---|---|
| `needs_input` | не хватает данных (например, образ приложения) | заполнить свойство в инспекторе — кнопка «Показать на холсте» |
| `no_cluster` | в зоне компонента нет кластера Kubernetes | добавить кластер или выбрать другое размещение |
| `hosting` | размещение `vm`/`managed` | выбрать `kubernetes`, если компонент должен жить в кластере |
| `unsupported` | шаблон не может выразить схему честно (например, Redis между кластерами) | изменить схему или написать свой шаблон |
| `no_generator` | для вида нет генератора | добавить шаблон под вашу платформу |
| `template_error` | ошибка выражения в шаблоне (указан путь) | исправить шаблон в админ-панели |
| `no_template`, `disabled` | шаблона нет / выключен | создать или включить шаблон |
| `no_workload` | остались одни арбитры | — |

## Форматы

### Манифесты Kubernetes (`kubernetes`)

```
README.md                    кластеры, команды применения, предварительные требования, секреты, не сгенерированное
<кластер>/
  kustomization.yaml
  namespaces.yaml            пространства имён, в которых лежат объекты
  <сервис>-<объект>.yaml     один объект на файл (cluster, objectstore, scheduledbackup, …)
  prerequisites/*.values.yaml  значения чартов операторов
```

```bash
cd app-dc1
helm upgrade --install cnpg cloudnative-pg/cloudnative-pg --namespace cnpg-system --create-namespace --version 0.29.1 --wait   # из README
kubectl apply -k .
```

### Helm (`helm`)

`helmfile.yaml` на кластер: релиз `namespaces` (все пространства имён создаются одним чартом — ни один релиз не создаёт и не делит
пространство имён), операторы, чарты компонентов (Traefik, kube-prometheus-stack, Argo CD, Vault …) и локальный чарт `workloads`
с объектами операторов. Релизы ждут (`needs`) только те операторы, которые им нужны.

```bash
cd app-dc1 && helmfile diff && helmfile apply
```

### Terraform / OpenTofu (`terraform`)

Провайдеры `hashicorp/kubernetes` и `hashicorp/helm` (версии — `export.terraformProviders`). На кластер два шага, потому что
`kubernetes_manifest` читает схему CRD при планировании, а CRD ставит оператор:

```
<кластер>/
  00-platform/   пространства имён, операторы и чарты (helm_release), значения чартов
  10-workloads/  kubernetes_manifest для каждого файла из manifests/ (те же объекты, что в формате kubernetes)
```

```bash
cd app-dc1/00-platform && tofu init && tofu apply
cd ../10-workloads     && tofu init && tofu apply
```

Пределы языка шаблонов — настройки движка: `export.templateLimits.fuel` (бюджет инструкций одного выражения) и `export.templateLimits.maxItems`
(самый длинный список в одном `$each`). Шаблон, который их превысит, попадает в отчёт как `template_error`, остальные компоненты генерируются.

Состояние: блок `backend` берётся из `export.terraformBackend`; `{arch}`, `{cluster}`, `{stage}` подставляются, поэтому у каждого шага свой
ключ состояния (по умолчанию — локальный файл; для командной работы укажите удалённый бэкенд).

## Как проверяется

`make iac-check` (в контейнерах, ничего не ставится на хост) для каждой эталонной архитектуры и демо-проекта генерирует все три формата и:

1. строит `kubectl kustomize`;
2. проверяет **каждый** объект `kubeconform --strict` по схемам Kubernetes и **CRD закреплённых версий операторов** (скачиваются из
   чартов, `additionalProperties: false`: опечатка в поле — ошибка; самопроверка убеждается, что валидатор действительно отвергает опечатку);
3. рендерит `helm template` каждый релиз helmfile (с нашими значениями) и валидирует результат;
4. выполняет `terraform init / validate / fmt -check` каждого шага с настоящими провайдерами.

Те же проверки запускает CI (job `iac`). Так были найдены и исправлены реальные ошибки шаблонов (строка вместо числа в
`RedisSentinel`, обязательное поле `image` экспортёра) — проверка не декоративна.

## Шаблон IaC

Шаблон — JSON-документ (Админка → Шаблоны IaC; конфиг-элемент вида `iac`, `id` = id вида компонента). Выражения проверяются при сохранении:
опечатка не дойдёт до экспорта; ошибка во время генерации не ломает остальное — компонент попадает в отчёт как `template_error` с путём
(`objects[0].body.spec.storage.size`).

```jsonc
{
  "id": "postgresql",
  "title": {"ru": "…", "en": "…"},
  "enabled": true,
  "target": "kubernetes",            // или "none" + "reason": где/как компонент разворачивается иначе
  "granularity": "unit",              // unit — нагрузка на сервис и кластер; node — на каждый узел
  "requires": ["cnpg", {"id": "barman-cloud", "when": "backupReady"}],   // операторы из export.k8s.operators
  "unsupported": [{"when": "unit.multiSite", "text": {"ru": "…", "en": "…"}}],     // честный отказ
  "needs": [{"prop": "image", "hint": {"ru": "…", "en": "…"}}],           // без этого не генерируем
  "vars": [{"name": "image", "expr": "'ghcr.io/cloudnative-pg/postgresql:' ~ p.version"}],
  "objects": [{"id": "cluster", "when": "…", "body": { "apiVersion": "…", "kind": "…", "metadata": {"name": "{{ name }}"}, "spec": {"instances": "{{ site.instances }}"} }}],
  "releases": [{"id": "traefik", "name": "{{ name }}", "namespace": "{{ ns }}", "chart": "traefik", "repo": "https://…", "version": "41.7.1", "values": {…}}],
  "secrets": [{"when": "…", "name": "{{ name }}-backup-credentials", "keys": ["ACCESS_KEY_ID"], "hint": {…}}],
  "notes": [{"when": "…", "level": "warn", "text": {"ru": "…", "en": "…"}}]
}
```

### Язык шаблонов

Любая строка может содержать `{{ выражение }}` (синтаксис выражений Jinja, движок [minijinja](https://github.com/mitsuhiko/minijinja)
в строгом режиме и с ограничением числа инструкций; ввода-вывода нет).

* строка из **одного** выражения сохраняет тип (`"{{ site.instances }}"` → число, `"{{ p.tags }}"` → список);
  иначе результат — текст: `"{{ p.diskGb }}Gi"` → `"500Gi"`;
* значение `none` **исчезает** вместе с ключом, а пустой после этого объект или список — вместе с ним: так выражаются необязательные поля.
  Обращение к неизвестной переменной — ошибка шаблона (опечатка не пройдёт молча), а `p.<свойство>` для объявленных свойств вида всегда
  определено (`none`, если не задано);
* директивы: `{"$if": выражение, "then": …, "else": …}`, `{"$each": выражение, "as": "x", "index": "i", "do": …}` (в массиве
  результаты вклеиваются), `{"$merge": [объект, …]}`, `{"$raw": …}` (без вычислений), `{"$when": выражение, "ключ": …}` внутри объекта;
* фильтры `slug` (DNS-1123, с транслитерацией кириллицы), `default`, `int`, `string`, `min`, `max`, `sum`, `join`, `length`, `select`,
  `map(attribute=…)` и остальные стандартные; функция `fail('текст')` прерывает генерацию объекта;
* результат — структура, а не текст: YAML и HCL пишутся из неё, поэтому имя узла с кавычками, переводом строки или `${…}` не может
  сломать файл или внедрить лишние ключи (покрыто тестами).

### Что доступно в выражениях

| Переменная | Содержимое |
|---|---|
| `p` | свойства ведущего узла нагрузки (все объявленные свойства вида; `none`, если не заданы) |
| `name`, `ns` | имя нагрузки (из `id` группы/узла: переименование на холсте не пересоздаёт ресурс) и пространство имён (по категории: `export.k8s.namespaces`) |
| `unit` | `key`, `name`, `slug`, `kind`, `behavior`, `traits`, `multiSite`, `sites[]` (`cluster`, `role`, `instances`, `zones`, `members`), `members[]` |
| `site` | часть сервиса в этом кластере: `role` (`primary`/`replica`), `instances`, `zones`, `members[]` (`id`, `name`, `zone`, `role`, `replicas`, `props`) |
| `primary` | `cluster`, `namespace`, `name` ведущей площадки (для реплика-кластеров) |
| `cluster` | `name`, `slug`, `nodes`, `zones`, `props` |
| `replication` | `syncLocal`, `syncCross`, `asyncLocal`, `asyncCross`, `syncBlock`, `edges[]` — связи репликации внутри сервиса |
| `backup` | `enabled`, `target` / `targets[]` — хранилище копий (его `props`, `edge.intervalSeconds`) |
| `has` | какие признаки есть в схеме (`has.monitoring`) |
| `arch`, `req`, `k8s`, `lang`, `labels` | имя схемы, требования, настройки `export.k8s` (кроме операторов), язык, общие метки |
| из `vars` | именованные выражения шаблона, считаются по порядку |

### Свой генератор

Допустим, в каталоге есть вид `my_cache`, который у вас — Deployment с образом из свойства `image`:

```json
{
  "id": "my_cache",
  "target": "kubernetes",
  "needs": [{"prop": "image"}],
  "objects": [{
    "id": "deployment",
    "body": {
      "apiVersion": "apps/v1", "kind": "Deployment",
      "metadata": {"name": "{{ name }}", "namespace": "{{ ns }}"},
      "spec": {
        "replicas": "{{ site.instances }}",
        "selector": {"matchLabels": {"app": "{{ name }}"}},
        "template": {"metadata": {"labels": {"app": "{{ name }}"}}, "spec": {"containers": [{"name": "cache", "image": "{{ p.image }}"}]}}
      }
    }
  }]
}
```

Для видов вне Kubernetes (ВМ, облачные сервисы) можно добавить Terraform-генераторы под вашего провайдера — это отдельное расширение; сегодня
такие компоненты честно попадают в «не сгенерировано».

## Подводные камни, которые учтены

| Камень | Решение |
|---|---|
| Операторы и CRD должны существовать до объектов | у Terraform два шага; у Helm — `needs`; у kustomize — команды установки в README |
| Разные версии API (Strimzi 1.x обслуживает только `v1`) | версии операторов закреплены, CRD берутся из чартов этих версий и проверяются строго |
| Устаревшие/закрытые проекты (ingress-nginx, образы Bitnami) | в шаблонах — поддерживаемые решения (Traefik, операторы CNPG/Strimzi/OpsTree); замена — правка шаблона |
| Репликация между кластерами | реплика-кластер CNPG асинхронен: если схема объявляет `sync` между кластерами, экспорт предупреждает о RPO > 0 |
| Секреты | никогда не генерируются; перечислены, с подсказкой откуда копировать |
| Бэкапы | WAL архивируется непрерывно, базовые копии — раз в сутки; без `bucket` у хранилища бэкап не выдумывается, а выводится предупреждение |
| Имена | имя ресурса — из стабильного `id`, не из названия; длина ограничена, чтобы суффиксы укладывались в 63 символа |
| Пространства имён | один чарт создаёт все (Helm), `kubernetes_namespace_v1` (Terraform), `namespaces.yaml` (kustomize) — без конфликтов «namespace already exists» |
| Состояние Terraform | отдельный ключ на кластер и шаг; удалённый бэкенд — в настройках |
