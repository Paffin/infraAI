# Эталонные архитектуры

Готовые схемы для типовых задач: с них начинают проект («Новый проект → Начать с…»), на них смотрят, как выглядит «правильно» для данной задачи, и на них держатся тесты движка.
Каждая — обычная схема проекта (зоны, компоненты, связи, требования): её можно открыть, менять, проверять и экспортировать в IaC так же, как свою.

## Что проверяют тесты

Любой файл `backend/crates/engine/defaults/templates/*.json` попадает в сборку сам (`build.rs`), и без отдельного перечисления каждая схема проходит:

* **правила**: ни одной критичной находки (`all_reference_templates_have_no_critical_findings`); у поставляемых схем нет и рисков, а оценка — 100 из 100 (проверяйте `infra-architect check <файл>`);
* **доступность**: ожидаемая доступность не ниже той, что схема сама заявляет в требованиях (`every_design_that_ships_meets_the_target_it_carries`);
* **шлюз CLI**: `infra-architect check --fail-on critical` проходит (`the_shipped_reference_designs_pass_their_own_gate`; в CI то же делается в образе, а SARIF проверяется по схеме);
* **трафик**: на каждой схеме и каждом сценарии потоки по связям складываются в нагрузки таблицы ёмкости, при норме ничего не теряется (`traffic.rs`);
* **галерея**: есть теги, значок, порядок, название и описание на двух языках (`every_shipped_template_can_be_found_in_the_gallery`);
* **IaC**: `make iac-check` выгружает каждую схему в Kubernetes, Helm и Terraform и проверяет результат по настоящим схемам, чартам и провайдерам.

## Как они написаны

Первые восемь — JSON, написанный руками. Остальные пишутся кодом в `deploy/templates/` — небольшим языком над теми же понятиями (зона, компонент, связь), в котором уже есть то, чего требуют правила
(шифрование на диске, пулер соединений, копии в неизменяемом хранилище вне домена отказа, измеренная задержка синхронных связей, TLS между площадками):

```python
# deploy/templates/t_my_design.py
from lib import Arch, backup_props, requirements, store

a = Arch("my-design", ("Моя архитектура", "My architecture"), ("Что это — в двух предложениях", "What it is in two sentences"),
         "HA", 21, ["ha", "kubernetes"], requirements(3000, 30, 300, 0, 1500000, "site", 99.95), "Название в схеме", "Заметки к схеме")
az = {x: a.zone(f"az-{x}", f"AZ {x.upper()}", "az", geo="eu-1", costModel="cloud") for x in "abc"}
a.node("users", "users", "Пользователи")
...
TEMPLATE = a
```

```bash
python3 deploy/templates/build.py            # написать defaults/templates/<id>.json (в CI — --check)
infra-architect check backend/crates/engine/defaults/templates/my-design.json --fail-on never   # что скажет движок
cargo test -p engine --test engine --test reliability --test traffic
```

`build.py` до записи проверяет схему по каталогу (виды, варианты и роли, типы зон и связей, концы связей), а оценка *хорошая ли это схема* — за движком. Четыре облачных схемы собираются одним построителем
(`cloudweb.py`): различается только то, какой продукт чем у провайдера является.

### Что узнали, пока их писали

* **Региональные управляемые сервисы стоят вне зон** (`zoneId: null`): балансировщик, объектное хранилище, очередь, секреты облака не падают вместе с зоной. Сервисы с primary и репликами (база, кэш) и приложение — в зонах.
* **Копии лежат вне домена отказа**: для облака — во втором регионе (или у другого поставщика), для своих ЦОД — на третьей площадке; иначе `DR-BKP-02` не пропустит.
* **Доступность управляемой схемы — произведение SLA звеньев.** Цепочка из десяти сервисов с SLA 99,9–99,99 % даёт около 99,8 %, поэтому облачные схемы заявляют 99,7 %, а бессерверная — 99,5 %: цель, которую схема не может выполнить, честнее не писать.
* **Нагрузка считается в запросах.** Пакетная запись (поток событий в ClickHouse) — это `fanout` меньше единицы на связи, а не «20 тысяч запросов в секунду к базе»; у подов с пакетной обработкой есть своё свойство `rpsPerReplica`.
* **Разные сервисы за одним шлюзом — не копии.** Правило «параллельные узлы сгруппированы» различает копии одного сервиса и разные сервисы по тому, куда они ходят дальше (`group_hygiene`).
* **Стоимость управляемых сервисов** считается по «эквивалентной мощности» (vCPU/RAM/диск, которые вы задаёте): у платных по использованию сервисов (очередь, секреты) цифра условная, поэтому у них указан минимальный размер.
