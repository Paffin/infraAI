# Подводные камни и как они решены

Источник — критический аудит концепции (12 слабых мест и перечень «подводных камней») и требования к сервису: бест-практис,
отказоустойчивость, лёгкая масштабируемость, катастрофоустойчивость, понятность с первого взгляда, всё настраивается, без хардкода.

## Двенадцать слабых мест концепции

| № | Слабое место | Риск | Как решено | Где |
|---|---|---|---|---|
| 1 | LLM без строгой модели | галлюцинации, несовместимые компоненты | типизированный граф; ответ модели проходит структурированный вывод, санитизацию под каталог, валидацию ссылок, ремонт и проверку движком | `engine::model`, `llm/pipeline.rs` |
| 2 | Схемы без инженерной семантики | HA нельзя доказать | у связей — семантика (зависимость / репликация / кворум / бэкап / управление), у компонентов — поведение и признаки, у зон — уровень отказа | `engine::catalog` |
| 3 | Проверяется лишь наличие резервов | ложная уверенность в HA | симуляция отказов с кворумом, fencing, отказными доменами; правила считают последствия, а не наличие рамочки «реплика» | `engine::sim`, [SIMULATION.md](SIMULATION.md) |
| 4 | Сеть не учитывается | нереализуемая топология | попарная связность площадок, разрыв канала как сценарий, `transitRouting`, GSLB/DNS-TTL в RTO, L4/L7-узлы, правила на TLS, сегментацию, WAF, RTT синхронных связей | правила `NET-*`, `DR-NET-*` |
| 5 | DR как «второй ЦОД» | потеря данных, split-brain | RPO/RTO как проверяемые цели; fencing и арбитр; witness на независимой площадке; восстановление из бэкапа с временем и окном потерь; проверка восстановления (`restoreTestedDays`); потеря данных безвозвратно = нарушение RPO | `DR-*`, `HA-QRM-*`, `HA-WIT-01` |
| 6 | Нет модели нагрузки | ошибки масштабирования | RPS пика + рост → нагрузка по юнитам через `fanout`, ёмкость на экземпляр, ёмкость при потере площадки, «холодный» кэш | `CAP-*`, `sim` |
| 7 | Нет бюджетных ограничений | избыточная стоимость | оценка стоимости из настраиваемого прайса, бюджет как требование, правило `COST-01`, вкладка «Стоимость» с разбивкой | `engine::cost` |
| 8 | Скрытые зависимости | общий SPOF | граф зависимостей; SPOF-анализ симуляцией отказа каждого узла/экземпляра; общие отказные домены; запрет циклов | `HA-SPOF-01`, `HA-DEP-01` |
| 9 | Небезопасные AI-изменения | порча проекта | ИИ только предлагает; предпросмотр на холсте, diff, оценка «до/после», явное применение, версия перед применением, откат | [LLM.md](LLM.md) |
| 10 | Нет связи с реальной средой | дрейф проекта | JSON-экспорт/импорт, **сравнение с фактом** (дрейф) через `/api/diff` и подсветка расхождений на холсте; GitOps-клиент может присылать снимок среды по API | Версии → «Дрейф» |
| 11 | Нет доказательной базы | недоверие к выводам | у каждой находки — правило, «почему это важно», ссылки, воспроизводимый сценарий отказа («Показать отказ»), отпечаток; оценка детерминирована | [RULES.md](RULES.md) |
| 12 | Слишком широкий MVP | долгая разработка | узкий домен: on-premise/hybrid, Kubernetes и ВМ, PostgreSQL/Redis/Kafka, балансировщики, 2–3 площадки; всё остальное добавляется как данные (каталог) | каталог по умолчанию |

## Подводные камни из аудита

| Камень | Решение |
|---|---|
| Ложные гарантии («HA 100 %») | статусы `критично / риск / нет данных / ок / не применимо`; предпосылки без данных — `нет данных`; «достоверность оценки» рядом с баллом; значения «по допущениям» помечены |
| Комбинаторный взрыв сценариев | сценарии строятся структурно (площадки, пары, каналы, гео, узлы), ограничены `scenarios.maxCount`; SPOF — отказ единичных элементов, не перебор подмножеств |
| Детерминированность | проверки не зависят от ИИ, времени и случайности; тесты на эталонных архитектурах с известными дефектами (демо-проект) |
| Вендорские ограничения (K8s, PostgreSQL, Ceph, VMware, облачные LB) | каталог, правила и допущения — данные: вид компонента с поведением и свойствами добавляется в админ-панели без кода |
| IaC: секреты, state, порядок развёртывания, заглушки | настоящий экспорт без заглушек: шаблоны по видам компонентов, честный отчёт «не сгенерировано», двухшаговый Terraform (CRD до объектов), `needs` в helmfile, отдельный state на кластер и шаг; секреты не генерируются; результат проверяется по схемам CRD закреплённых версий, `helm template` и `terraform validate` ([IAC.md](IAC.md)) |
| Дрейф проекта и реальности | см. п. 10 выше |

## Подводные камни реализации

| Камень | Решение |
|---|---|
| Конкурентное редактирование | оптимистичные ревизии черновика, `409 conflict`, баннер «загрузить версию сервера»; применение ИИ-операций к актуальному черновику |
| Потеря правок при сбое сети | автосохранение с повтором и растущей паузой; предупреждение при закрытии вкладки с несохранённым |
| Падение реплики во время задачи ИИ | задача в БД с heartbeat; «уборщик» на другой реплике помечает её `interrupted`; клиент опрашивает, а не держит соединение |
| Разные реплики — разная конфигурация | счётчик ревизии конфигурации в БД, кэш с короткой жизнью |
| Одновременный старт реплик | миграции, посев и создание администратора — под `pg_advisory_lock` |
| Перезапись ваших правок обновлением | встроенные элементы помечены хэшем и флагом `modified`; изменённые не затираются, о новой версии сообщается |
| Утечка секретов | секреты шифруются (AES-256-GCM), не возвращаются API, не попадают в экспорт и аудит; логи и шаги задач не содержат ключей |
| Утечка данных в провайдера ИИ | `dataCollection: deny`, `zdr`, список провайдеров, отправка заметок — отдельный переключатель; сырые ответы не пишутся (`logPrompts`) |
| Неуправляемые расходы на ИИ | месячный бюджет, лимит в час на пользователя, одна задача на проект, учёт стоимости из ответа OpenRouter |
| Модель не поддерживает параметр запроса | параметры подбираются по возможностям модели; «No endpoints found» → повтор в урезанном виде; запасные модели |
| Строгое декодирование «обнуляет» свободные карты (свойства узлов приходят пустыми) | режим `auto`: схема только для строго описанных ответов, генерация и правка — `json_object`; тест следит, что схемы с картами не уходят как `json_schema`, а схема операций объявляет все поля |
| Невалидный/обрезанный ответ модели | разбор, санитизация, ремонт по ошибкам, ошибка `llm_truncated` с понятным сообщением, а не битая схема |
| CSRF, XSS | проверка `Origin`, SameSite=Lax, HttpOnly, строгий CSP без inline-скриптов; значения из каталога выводятся как текст |
| Брутфорс паролей | Argon2id, блокировка аккаунта, лимит по IP, минимальная длина пароля — настройками |
| Выданный пароль остаётся «временным» | пока пароль не сменён, API отвечает `403 password_change_required` на всё, кроме смены пароля |
| «Нет данных» не должно выглядеть как «хорошо» | объективы (RTO, RPO, площадка, SPOF, ёмкость) показывают `нет данных` отдельным цветом; новая связь без TLS — вопрос, а не молчаливое «ок» |
| «Нет данных» без выхода: непонятно, *что* заполнить и *где* | у находки `no_data` движок указывает `needs` — поле требований или свойство узла/связи/зоны; кнопка открывает нужную вкладку или инспектор на нужной группе, ставит фокус и подсвечивает поле. Тест на настоящем выводе движка следит, что каждое такое свойство есть в каталоге (`az` когда-то не имел `geo` — путь вёл в никуда) |
| Цель «RTO ≤ 5 мин: 35 с» — число без доказательства | плашки целей кликабельны: открывают худший сценарий на холсте (тот, что дал число), поле для заполнения или план ёмкости |
| «Хватит ли мощности, если нагрузка вырастет вдвое» | вкладка «Ёмкость»: нагрузка/ёмкость каждого сервиса, худший отказ, сколько экземпляров нужно для запаса; «а если ×N» считается на клиенте (нагрузка линейна по RPS), запас до перегрузки и при отказе — готовыми числами |
| Большая схема нечитаема при отдалении | семантический зум: ниже порога карточка прячет подзаголовок, а имя остаётся одного экранного размера; ещё дальше — цветные плитки видов (обзор); пороги — в `lib/lod.ts` |
| Массовые правки: переносить, группировать, копировать десятки узлов по одному | выделение рамкой / Shift+клик / Ctrl+A, перенос узлов вместе, «в сервис», «в зону» (карточки встают на свободные места зоны, зона растёт), копия с внутренними связями; каждое действие — один шаг отмены |
| Невидимые возможности | палитра команд Ctrl/⌘+K: узлы, зоны, замечания, сценарии отказов, добавление компонентов, панели; окно «Горячие клавиши» (`?`) строится из той же таблицы, что и подсказки |
| Список проектов не отличает проекты | миниатюра схемы на карточке (данные — `thumb` в списке, без имён и свойств, только для `limits.listThumbnails` последних проектов; остальные подгружаются при прокрутке по три), копирование проекта, сортировка и фильтр «есть критичное или риск» |
| Схему нужно вставить в документ | экспорт «Схема (SVG)»: тот же рисунок, что у миниатюр, имена экранируются; SVG строится в браузере по данным, без DOM и canvas |
| Исправление «улучшает» и портит оценку | исправления — детерминированные патчи, после применения всё пересчитывается; тест следит, что устранение потери данных не добавляет критичных находок |
| Раскладка «каша» у сгенерированных схем | детерминированная авто-раскладка по рядам глубины и площадкам; новые узлы встают в свободные слоты своей зоны |
| Числа, зашитые в код (паузы, пороги, лимиты) | у каждого — ключ в реестре настроек и диапазон: тайминги редактора (`editor.*`, приходят в `/bootstrap`), лимит попыток входа, кэш пользователя, периоды фоновых проверок, срок хранения удалённых проектов, повторы и таймауты OpenRouter, число замечаний в подсказке, пределы языка шаблонов IaC. Запасные значения во фронтенде равны значениям реестра — это проверяет тест |
| «Сервисов — десятки, вариантов — сотни»: плоский список видов не помогает выбрать | каталог — продукты (105), сгруппированные по **функции**, у каждого — варианты развёртывания (207) и таблица версий; библиотека складывает продукты функции вместе, поиск находит продукт и по названию варианта ([CATALOG.md](CATALOG.md)) |
| Один и тот же продукт ведёт себя по-разному в зависимости от развёртывания (Patroni и Amazon RDS; Vault на репликации и на Raft) | **вариант** меняет поведение, признаки, свойства по умолчанию, роли, ёмкость и цену; кворум моделируется по власти над переключением (внешний DCS / собственный / провайдер) — управляемый сервис не получает требование «поставьте etcd» |
| Версии «из головы» и устаревшие сроки поддержки | таблицы выпусков (endoflife.date) — данные в БД; движок не читает часы, дата — аргумент; `VER-01` судит только заявленную версию и честно говорит «нет данных», если таблица старше `engine.lifecycle.staleDays`; обновление — кнопкой, по расписанию, из CI |
| Обновление таблиц версий как дыра: SSRF, опустошение таблицы, N реплик одновременно | разрешены только адреса из `versions.sourceBases`, без логина в адресе; плохой ответ не меняет таблицу; слот обновления берётся условной записью в `meta`; свежая таблица не затирается старой при обновлении образа |
| Схема размещения «на два ЦОД» не масштабируется до пяти и десяти | генератор размещения: любое число площадок, регионов и стоек, `k` одновременных отказов, арбитры на нечётный кворум, резервная площадка, внешняя площадка копий; 620 комбинаций «продукт × вариант × число площадок» проверяются тестом ([PLACEMENT.md](PLACEMENT.md)) |
| Разрыв связи между тремя и более площадками, а не «одна ссылка» | сценарий `isolate`: группа площадок отрезана от остальных, но продолжает работать; правила `DR-NET-03/04` ([SIMULATION.md](SIMULATION.md)) |
| Параметры генератора размещения, зашитые в код (задержки, имена, число голосов) | схемы, платформы и параметры генератора — конфигурационные элементы `placement.*`, редактируются в админ-панели |
| Зависимость от внешних реестров при сборке | сборка образа параметризуется зеркалом (`REGISTRY`) и секретом с CA; базовые образы — по версии |
