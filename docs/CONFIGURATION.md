# Конфигурация

Принцип: **в переменных окружения — только то, что нужно до подключения к БД, и секреты загрузки. Всё остальное — настройки в базе данных,
которые меняются в админ-панели без перезапуска.** Хардкода предметной области (видов компонентов, правил, порогов, промптов, моделей, цен) нет:
всё это — данные с понятными значениями по умолчанию.

## Три уровня

| Уровень | Где хранится | Как менять |
|---|---|---|
| **Окружение** | переменные процесса | при развёртывании (таблица ниже) |
| **Настройки** (реестр из ~60 ключей) | таблица `settings`; секреты зашифрованы | Администрирование → Настройки / OpenRouter |
| **Конфигурационные элементы** | таблица `config_items` (виды компонентов, типы связей/зон, категории, общие свойства, правила, шаблоны, промпты, допущения движка) | Администрирование → Каталог / Правила / Шаблоны / Промпты / Движок |

Встроенные значения лежат в репозитории (`backend/crates/engine/defaults/*.json`, `backend/crates/server/defaults/*.json`) и при старте
копируются в БД. Элемент помечен хэшем встроенной версии: если вы его не меняли, обновление приложения обновит и его; если меняли —
ваша версия остаётся, а в списке появляется метка «доступна новая версия по умолчанию» (можно сбросить). Свои элементы (`origin: custom`) приложение не трогает.

Изменение любого элемента увеличивает счётчик ревизии; все реплики подхватывают его в течение нескольких секунд (`CONFIG_CACHE_TTL_MS`).

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `DATABASE_URL` | — (обязательна) | строка подключения PostgreSQL |
| `APP_SECRET` | — (обязательна в production; ≥ 32 символов) | подписывает сессии и шифрует секреты в БД (AES-256-GCM); одинаковая на всех репликах. Потеряете — сохранённые секреты (ключ OpenRouter) придётся ввести заново, сессии сбросятся |
| `APP_ENV` | `production` | `development` / `dev` / `test` — временный секрет, человекочитаемые логи, cookie без `Secure` |
| `HOST`, `PORT` | `0.0.0.0`, `8080` | адрес прослушивания |
| `WEB_DIR` | `/app/web` | каталог собранного фронтенда |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | `admin@example.com`, случайный | первый администратор (создаётся, только если пользователей ещё нет). Без пароля он генерируется и печатается в лог один раз; пароль нужно сменить при первом входе |
| `OPENROUTER_API_KEY` | — | ключ OpenRouter; ключ из админ-панели (зашифрован в БД) имеет приоритет |
| `COOKIE_SECURE` | `true` в production | флаг `Secure` у cookie сессии; `false` — для доступа по http без TLS |
| `TRUST_PROXY` | `false` | доверять `X-Forwarded-For` / `X-Forwarded-Host` обратного прокси (IP в аудите, лимит попыток входа, проверка Origin) |
| `METRICS_TOKEN` | — | если задан, `/metrics` требует `Authorization: Bearer …` |
| `DB_MAX_CONNECTIONS` | `10` | размер пула на реплику |
| `DB_CONNECT_TIMEOUT_SECONDS` | `120` | сколько ждать БД при старте (повторы с паузой) |
| `SHUTDOWN_GRACE_SECONDS` | `25` | сколько после SIGTERM дорабатывать активные задачи ИИ |
| `DRAIN_SECONDS` | `3` | сколько после SIGTERM продолжать принимать запросы, пока балансировщик видит `/readyz` = 503 |
| `CONFIG_CACHE_TTL_MS` | `5000` | период проверки ревизии конфигурации в БД |
| `INSTANCE_ID` | случайный | подпись реплики в логах и задачах ИИ |
| `SEED_DEMO_PROJECT` | настройка `app.seedDemoProject` | `false` — не создавать демо-проект при первом запуске (переопределяет настройку; удобно до того, как админ успел её изменить) |
| `LOG_JSON` | `true` в production | JSON-логи; `RUST_LOG` управляет уровнем |

В compose-файлах: `POSTGRES_PASSWORD`, `APP_PORT`, `REGISTRY` (зеркало базовых образов); см. `.env.example`.

## Конфигурационные элементы

| Вид (`kind`) | Что описывает |
|---|---|
| `catalog.kind` | вид компонента: категория, аббревиатура и цвет значка, поведение (`stateless` / `primary_replica` / `consensus` / `quorum_log`), признаки (`traits`), роли, свойства с типами и подписями, строка под названием, производительность на экземпляр |
| `catalog.edge_type` | тип связи: семантика (`dependency` / `replication` / `membership` / `backup` / `control`), стиль линии, направленность, слой, свойства |
| `catalog.zone_type` | тип зоны: уровень (`group` / `rack` / `site` / `geo`), цвет, свойства (Tier, гео-домен, модель стоимости) |
| `catalog.category`, `catalog.common_props` | категории библиотеки; свойства, общие для всех видов (ёмкость, заметки, масштабирование) |
| `rule` | правило проверки ([RULES.md](RULES.md)) |
| `template` | эталонная архитектура (шаблон проекта) |
| `prompt` | системный промпт ИИ ([LLM.md](LLM.md)) |
| `engine` | допущения, веса оценки, ограничения сценариев, прайс стоимости, тексты экспорта |

Чтобы добавить, например, **Ceph** или **VMware vSphere**: Каталог → «Новый элемент» → вид с поведением, признаками и свойствами;
для специфичных проверок — правило типа `prop` по этим свойствам. Код не меняется, пересборка не нужна; новый вид сразу появляется в
библиотеке, инспекторе, подсказках ИИ и проверках.

## Перенос и резервная копия конфигурации

Администрирование → Бэкап: экспорт всего изменённого (настройки + изменённые и свои элементы) одним JSON и импорт на другой
стенд. Импорт всегда сначала выполняется в режиме проверки (`dryRun`): показываются проблемы и число изменений, применить можно только
неизменённый проверенный файл. **Секреты никогда не попадают в экспорт.** Те же операции доступны по API (`/admin/config-export`,
`/admin/config-import`).
