# ADR-0006. IaC из редактируемых шаблонов, без заглушек, с проверкой по настоящим артефактам

**Статус:** принято (заменяет первоначальный «каркас» Terraform/Helm с модулями-заглушками)

## Контекст

Первый экспорт Terraform создавал модули-заглушки (`terraform_data`), а Helm ссылался на несуществующий репозиторий: он «валидировался», но
ничего не разворачивал и создавал ложное ощущение готовности — прямо против принципа «никогда не ложно-зелёный». Экосистема при этом быстро
меняется (в Strimzi 1.x обслуживается только `v1`, ingress-nginx выводится из поддержки, образы Bitnami переехали), поэтому знание о том,
«как развернуть PostgreSQL в Kubernetes», не должно быть зашито в код.

## Решение

* Знание «вид компонента → объекты» — **данные**: шаблон IaC на вид (конфиг-элемент `iac`, правится в админ-панели). Шаблон — JSON с
  выражениями `{{ … }}` (minijinja, строгий режим, лимит инструкций) и несколькими директивами; результат — структура, из которой YAML и
  HCL пишут сами писатели, поэтому имена из схемы не могут сломать файл.
* Код знает только **как разместить**: кластеры (`clusterName`/зоны), размещение (`hosting`), площадки сервиса, порядок установки,
  пространства имён, три писателя (kustomize, helmfile, Terraform в два шага).
* Что сгенерировать нельзя — **не выдумывается**, а попадает в отчёт с кодом причины и подсказкой, что сделать
  (`needs_input`, `no_cluster`, `hosting`, `unsupported`, `no_generator`, …); шаблон может честно отказаться (`unsupported`) там, где схему
  нельзя выразить (Redis между кластерами, растянутая Kafka).
* Версии операторов **закреплены** в настройках; предупреждения о семантике (`sync` между кластерами CNPG невозможен) — часть шаблона.
* Результат проверяется **настоящими** инструментами (`make iac-check`, job CI `iac`): `kubeconform --strict` по схемам Kubernetes и CRD из
  чартов закреплённых версий, `helm template` с нашими значениями, `terraform validate/fmt`, `kustomize build`; самопроверка гарантирует,
  что валидатор отвергает опечатку.

## Последствия

* Покрыты виды, для которых есть честная, проверяемая схема (PostgreSQL/CloudNativePG, Kafka/Strimzi, Redis/OpsTree, приложение, Traefik,
  kube-prometheus-stack, Argo CD, Vault); остальные — в отчёте «не сгенерировано» с причиной. Расширение — шаблоном, без правки кода.
* Операторские CR зависят от закреплённых версий: обновление — осознанная правка настройки + `make iac-check`.
* Генерация вне Kubernetes (ВМ, облачные сервисы) — следующий шаг и делается теми же шаблонами; пока она честно отсутствует.
