# ADR-0003. Каталог, правила, промпты и допущения — данные

**Статус:** принято

## Контекст

Требования: «без хардкодов», «всё можно настроить», разные вендоры (K8s, PostgreSQL, Ceph, VMware, облачные LB) требуют разных правил, а админ-панель
должна быть полноценной.

## Решение

* Виды компонентов, типы связей и зон, категории, общие свойства, правила, шаблоны, промпты и допущения движка — JSON-документы
  (`config_items`), встроенные значения лежат в репозитории и копируются в БД при старте (с хэшем для безопасного обновления).
* Реестр настроек (`settings`) типизирован и описывает себя (подпись, пояснение, границы), поэтому админ-панель строит формы из него.
* Все тексты — `LText` (`{ru, en, …}`); движок отдаёт коды и переменные, а тексты подставляются из данных.
* Код содержит только *типы проверок* (26 универсальных), поведения компонентов (4) и семантику связей (5).

## Последствия

* Новый вид компонента/правило не требует релиза; изменения подхватываются репликами за секунды (ревизия конфигурации в БД).
* Нужна валидация данных при записи (сервер проверяет элементы по типам движка) и перенос между стендами (экспорт/импорт с `dryRun`).
* Встроенные значения обновляются вместе с образом, не затирая изменённые (`modified`, `updateAvailable`).
