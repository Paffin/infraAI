# ADR-0004. Stateless-реплики и PostgreSQL как единственное хранилище состояния

**Статус:** принято

## Контекст

Сервис сам должен быть отказоустойчивым, легко масштабируемым и катастрофоустойчивым — иначе странно проверять чужие архитектуры.

## Решение

* Реплики сервера идентичны и ничего не хранят: сессия — подписанная cookie, кэш конфигурации синхронизируется счётчиком ревизии в БД, задачи ИИ живут
  в БД с heartbeat, миграции/посев — под advisory-lock.
* Единственное stateful-звено — PostgreSQL; его HA/DR — задача платформы (оператор CloudNativePG или управляемая БД с PITR).
* Остановка — управляемая: `/readyz` → 503, дренаж, доработка задач ИИ; `/healthz` не зависит от БД, чтобы авария БД не вызвала перезапуск здоровых подов.

## Последствия

* Горизонтальное масштабирование — числом реплик (HPA), потеря реплики/зоны не заметна пользователю.
* RPO/RTO сервиса определяются настройкой PostgreSQL, а не приложением; восстановление = БД + образ + `APP_SECRET`.
* Нет шины сообщений и очереди: задачи ИИ читаются из БД; для текущей нагрузки (единицы задач в минуту на реплику) этого достаточно.
