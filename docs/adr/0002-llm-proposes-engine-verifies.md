# ADR-0002. LLM предлагает, движок проверяет, человек применяет

**Статус:** принято

## Контекст

Красивая схема не доказывает отказоустойчивость; LLM склонна к галлюцинациям (несовместимые компоненты, «резервы», которые не работают при
разделении сети). Требование — архитектура по бест-практис, которой можно доверять.

## Решение

1. Модель получает каталог, правила, схему и замечания и возвращает **структурированный** ответ (JSON по схеме) — полную схему или набор операций.
2. Ответ санитизируется под каталог, валидируется, при ошибках возвращается модели на ремонт; затем оценивается движком, по критичным замечаниям
   идёт доработка, безопасные замечания закрывает сам движок.
3. Результат — *предложение* с предпросмотром (diff, оценка до/после). Модель **не может** изменить проект. Применение — явное, с версией «до» и откатом.
4. Оценка, статусы и объяснения — только от движка; текст модели — рационале и допущения.

## Последствия

* Качество результата ограничено сверху движком: «зелёное» ИИ нарисовать не может.
* Дороже и дольше одного вызова (до нескольких раундов), поэтому — фоновые задачи с шагами и отменой.
* Работает с любой моделью OpenRouter, включая слабые на структурированном выводе (деградация до `json_object` и «только промпт», ремонт).
