# ADR-0007. Строго на записи, мягко на чтении: границы — данные, ошибка API — один JSON

**Статус:** принято

## Контекст

Схема с `replicas = 10¹²` сохранялась, и после этого каждая оценка, версия, экспорт и принятие риска по проекту отвечали `500` (сумма экземпляров переполняла `u32`; в релизной сборке она молча
заворачивалась и давала неверную доступность). Границы в каталоге были (`replicas` от 1 до 1000), но проверка их не читала, а максимум был лишь у 294 видов из 956: остальные переописывают свойство и о
максимуме молчат. Тем временем редактор отправляет на проверку то, что набрано, после каждой паузы: строгий отказ на таких путях превратил бы каждое полунабранное число в мигающий баннер. А 14 из 15
нечитаемых запросов получали ответ `text/plain` вместо одного JSON, обещанного в [API.md](../API.md).

## Решение

* **Один затвор — `engine::model::validate`.** Им пользуются все пути: сохранение, создание проекта, операции, предложения ИИ, ответ модели, `infra-architect check`. Он говорит одно и то же везде
  (`Issue = {level, code, message, subject}`), а у каждого кода есть тест, который портит эталонную схему ровно одним способом (список кодов сверяется с исходником затвора).
* **Строго на записи.** Что записывается, число вне диапазона не получает: `400 invalid_architecture` (или `ops_invalid`) с перечнем замечаний, где названы узел, свойство и допустимый диапазон. Ответ
  модели только *предлагает* ([ADR-0002](0002-llm-proposes-engine-verifies.md)): число вне диапазона у нового узла отбрасывается (не подгоняется — подогнанное выглядит правдоподобно, а модель его не
  писала), остальное возвращается модели на исправление вместе с теми же сообщениями.
* **Мягко на чтении.** Что только смотрят (`/evaluate`, `/simulate`, `/recommendations`, экспорт, версия), не отклоняется: то же замечание — предупреждение (`ValidationLimits::lenient`), так что проект,
  сохранённый до проверки, открывается и сохраняется снова, как только число исправлено. Структура (ссылки, виды, циклы) не смягчается: `/simulate`, `/recommendations` и `/ops/apply` отвечают `400`, а `/evaluate` возвращает её среди замечаний как ошибку. Движок держит у предела только число экземпляров
  (целое от 1 до `limits.maxReplicas`, складывается с насыщением); остальные числа читает как есть, и величина, посчитанная из числа вне диапазона, остаётся **без значения**, а не выдуманной.
  Размер схемы (узлы, связи, зоны) — предел того, кто её принимает, и в отчёт по сохранённой схеме не попадает.
* **Границы — данные** ([ADR-0003](0003-data-driven-configuration.md)). Диапазон свойства — `min`/`max` каталога, и вид, который границу не называет, берёт её у общего свойства **по полям**
  (`Catalog::prop_bounds`). Потолки — настройки движка (`limits` в `engine.json`: `maxReplicas`, `maxNumber`, `maxRpsPeak`, `maxGrowthPercent`). Области определения — доступность в (0, 100], время и
  деньги не отрицательные — математика, а не настройка. Каталог, у которого минимум выше максимума или значение по умолчанию вне диапазона, не сохраняется в админ-панели: он отклонял бы каждую запись.
* **Каждая ошибка API — `{"error": {"code", "message", "details?"}}`.** Свои `Json`, `Path` и `Query` вместо извлекателей axum отвечают тем же JSON на сломанное тело, неверный тип, чужой `Content-Type`,
  слишком большое тело и неверный идентификатор; неверный метод — `405` с `Allow`; потерянный файл в `/assets` — настоящий `404`. Таблица кодов в [API.md](../API.md) сверяется с исходниками сервера:
  код без строки в таблице не пройдёт тест.

## Последствия

* Основание `/ops/apply` читается мягко, а его результат записывается строго: операция, не исправляющая число вне диапазона, получает `400 ops_invalid`, и предложенное исправление другой находки на
  такой схеме не посмотреть, пока число не исправлено.
* Редактор получает предупреждение в `issues` там, где раньше получал ответ: пока он выводит все замечания одним баннером, а автосохранение числа вне диапазона получает `400` с английским текстом
  (доделывает фронтенд).
* Новое свойство со своим диапазоном получает проверку даром — граница берётся из каталога; новый код затвора обязан попасть в список тестов.
* Предел правится в настройках движка без пересборки; на установках, где администратор правил общее свойство «Экземпляры», остаётся его прежний максимум (он строже), пока элемент не сброшен.
* Заголовки безопасности (HSTS, `Cross-Origin-Resource-Policy`) сюда не входят: они — задача «безопасно по умолчанию».
