# Каталог по умолчанию

`backend/crates/engine/defaults/catalog.json` — каталог, с которым стартует чистая установка (виды компонентов, варианты,
функции, версии). Он собирается из исходников в этой папке, чтобы тысяча продуктов оставалась согласованной.
`catalog.json` руками не правят: правят исходник и собирают.

| Файл | Что в нём |
|---|---|
| `base.json` | исходные виды, написанные вручную (22 штуки), категории, типы связей и зон, общие свойства |
| `part_a.py` … `part_d.py` | первая, **основная** библиотека (105 продуктов): функции, варианты и виды, написанные вручную. Все эти виды получают признак `core` |
| `kinds_<имя>.py` | продукты, добавленные пачками по областям (`kinds_edge_a`, `kinds_data_b`, `kinds_security_a`, `kinds_ai`…): каждый модуль отдаёт `KINDS`, а при необходимости `FUNCTIONS` (новые функции по категориям) и `IAC` (класс честной подписи «шаблона нет» для функции). `build.py` находит модули сам |
| `forge.py` | заготовки продуктов (архетипы): `svc`, `app`, `lbsvc`, `appliance`, `saas`, `sqldb`, `qcluster`, `voters`, наборы признаков `T[...]`, цвета, `vself` / `vcloud` для вариантов |
| `arch.py`, `lib.py` | заготовки пониже: наборы свойств, поведение, рекомендуемая версия из таблиц выпусков |
| `checks.py`, `lint.py` | проверки исходников; линтер запускают, пока пишут модуль |
| `version_names.py`, `version_labels.json` | названия таблиц выпусков (`versions.json`) |
| `iac.py` | честные шаблоны IaC «не генерируется» для видов без проверенного генератора |
| `build.py` | сборка; здесь же значки: `FUNCTION_ICON` (значок функции — его носят все её виды), `CATEGORY_ICON`, `ZONE_ICON` |

```bash
python3 deploy/catalog/lint.py kinds_edge_a   # проверить один модуль (остальные читаются, чтобы найти повторы)
python3 deploy/catalog/lint.py                # проверить все
python3 deploy/catalog/build.py               # записать catalog.json, названия в versions.json и недостающие шаблоны IaC
python3 deploy/catalog/build.py --check       # проверить, что сгенерированное актуально (так делает CI)
python3 deploy/gen-docs.py                    # пересобрать таблицы в docs/ (CATALOG.md, IAC.md, CONFIGURATION.md)
```

## Как написать модуль

```python
from forge import *

FUNCTIONS = {"edge": [("ddos", "Защита от DDoS", "DDoS protection", "shield-alert")]}   # только новые функции; значок — из frontend/src/lib/icons.ts
IAC = {"ddos": "appliance"}                                                              # необязательно: класс подписи «шаблона нет»

KINDS = [
    svc("kong_mesh", "platform", "mesh", "KMS", "Kong Mesh", "Kong Mesh", ("описание…", "description…"), table=None, traits=T["platform"], replicas=2),
    saas("amazon_sqs", "data", "mq", "SQS", "Amazon SQS", "Amazon SQS", ("…", "…"), traits=T["mq"], cap=100000),
    sqldb("ibm_db2", "rdbms", "DB2", "IBM Db2", "IBM Db2", ("…", "…"), table="ibm_db2", cap=4000, variants=[vself("hadr", …), vcloud("cloud", …)]),
]
```

* **Описание** — пара `(ru, en)`: что за продукт и **как он отказывает / что нужно для HA** («пара с синхронизацией состояния; один узел — единая точка отказа»).
  Не больше двух предложений на язык; только то, в чём уверены. Неверное утверждение об отказоустойчивости хуже отсутствующего продукта.
* **Поведение** (`behavior`): `stateless`, `primary_replica`, `consensus` или `quorum_log` — так движок считает переключение и кворум.
* **Признаки** (`traits`) читают правила: `workload`, `balancer`, `datastore` (нужны `cap` и свойства — линтер проверит), `stateful` + `backup-required`,
  `cache` + `soft-dependency`, `mq`, `secrets`, `monitoring`, `gitops`, `waf`, `dns-routing`, `backup-target`, `managed`, `entry` / `external`, `telemetry`, `platform`…
  Признак, который не читает ничего, — тег для описания (линтер предупредит, но это не ошибка).
* **Сервис, который ведёт провайдер** (`saas(...)`): признаки `managed` и `provider-ha`. Экземпляров считать нечего: правила «два экземпляра» (`HA-APP-01`, `HA-LB-01`),
  «нет единой точки отказа» (`HA-SPOF-01`) его не трогают, ёмкость за него отвечает провайдер (своя ёмкость узла проверяется, только если архитектор указал `rpsPerReplica`),
  а доступность считается по SLA (`reliability.provider.byFunction` в `engine.json`). Какие признаки значат «провайдер сам решает» — настройка `assumptions.elasticTraits`.
* **Функция**: продукты одной функции взаимозаменяемы; первая в списке — «обычный выбор» (поэтому основные продукты идут первыми). Продукт, который **не** заменяет остальные
  (маршрутизатор оповещений рядом с системой мониторинга, HSM рядом с хранилищем секретов), получает функцию свою: иначе мастер размещения предложит его на место нужного.
* **Версии**: `table=` — идентификатор таблицы выпусков из `versions.json`; без таблицы `table=None` (свободное поле версии, срок поддержки не проверяется). Таблицы не выдумывают.
* **Варианты** — способы запуска, которые меняют отказ: топологии (Raft или ручное переключение) и версия, которую ведёт провайдер (`vcloud`). Вариантов «для красоты» не добавляют.

Мастер размещения предлагает в слое **каждый** продукт его функции (`tests/placement.rs` строит схему для каждого на 1–10 площадках и требует чистоты): продукт, у которого по его природе
нет автоматического переключения, записывают в `KNOWN_LIMITS` этого теста с причиной, а не прячут.

Значок вида — имя из набора интерфейса (`frontend/src/lib/icons.ts`): по умолчанию он общий для функции, свой задают через `icon=` в `kind()` / `k()` (или `"icon"` в `base.json`).
Вид без значка сборку не проходит, а имя, которого нет в наборе, не пропустит `python3 deploy/gen-docs.py`.

Версии по умолчанию в видах — это «рекомендуемая линия» из таблиц выпусков на день их снятия (самую новую линию,
которой больше 90 дней, предпочитая LTS), поэтому после `python3 deploy/versions-sync.py` каталог пересобирают и смотрят
разницу. Подробнее — `docs/CATALOG.md`.
